# Pet2Dial Skillmaker Audit

## Classification

Skill type: workflow automation with deterministic conversion and firmware build steps.

User framing: problem-first. The user wants Codex's desktop pet outside the Mac screen on M5Stack Dial; the skill chooses the needed scripts and hardware workflow.

Topology: sequential skill. No subagents.

## Contract Answers

1. Any compliant runtime must guide or execute a local workflow that converts the selected Codex custom pet into M5Stack Dial firmware and runs a BLE bridge for Codex state.

2. Success means a flashed Dial displays the selected Codex pet, receives running/review cards, and opens Codex threads when cards are clicked.

3. Persisted artifacts:

- `<project>/firmware/include/pet_frames.h` generated by conversion
- `<project>/firmware/.pio/build/m5dial/firmware.bin` generated by PlatformIO
- `<project>/state/seen_done_threads.json` generated by bridge at runtime
- `<project>/logs/bridge.log` if the user launches the bridge through a wrapper

4. Deterministic scripts:

- environment check: `scripts/pet2dial.py doctor`
- project template copy: `scripts/pet2dial.py init`
- dependency setup: `scripts/pet2dial.py setup-env`
- pet conversion: template `tools/convert_pet.py`
- build/upload/run/verify: `scripts/pet2dial.py`

5. Runtime-specific capabilities:

- BLE access is required for live sync.
- USB serial is required for firmware upload.
- macOS is required for `codex://threads` open behavior and current Codex Desktop paths.

6. Orchestrator-owned steps:

- choose whether to force-refresh an existing project
- decide whether a missing custom pet blocks progress
- run conversion and build commands
- interpret doctor/build/upload failures for the user

7. No delegation roles.

8. No subagent access matrix.

9. Fallback without subagents is the normal path.

10. No subagent context packet required.

## Scope Decision

The main path intentionally excludes:

- arbitrary image-to-pet generation
- LittleFS resource streaming
- multi-pet firmware bundles
- Unit Synth MIDI cues
- decoded Codex desktop asar internals

These were useful exploration topics during the original run, but they do not belong in the one-shot success path.

## Known Boundary

The skill mirrors Codex task state from local rollout files and maintains bridge-local review seen state. It does not currently consume Codex Desktop's internal Electron `thread-read-state-changed` IPC state because no stable public local persistence point was found during the run.
